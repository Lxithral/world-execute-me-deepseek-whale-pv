# REVIEW_T23a.md — 修 a) 确定性：段 K 峡谷滚动的"按渲染次数累加"（T23 的 FAIL 之一，已修）

> 改动文件：`src/scenes/k_storm.js`（`buildCanyon()` 的 `update()` 由**累积式**滚动改成**闭式相位**）。
> 症状（T23 的 `?scan=0.5` 全量 `?selftest`）：`画布 同 t:一致／乱序 24 点差 **1**（t=156.43）` —— 违反 §0「渲染是 t 的纯函数」。

## 词 → 事件 → 对象

| 项 | 实测（用 T24 修好的 `tools/render_probe.mjs`） | 根因 | 改动 | 修后实测 |
|---|---|---|---|---|
| 段 K 峡谷（乐句三，156–162s）的滚动日志贴图 | ① `render_probe --t 157.0`：**两遍渲染相差 400,684 像素**（差异铺满 12×8 网格、`maxd` 到 506）；② 同一 t **连渲 4 次**：`ab=389,096 / bc=400,896 / cd=386,578` ⇒ **每次渲染结果都不同**（不是"冷启动一次"）；③ 对照：`t=130.0` 与 `t=155.0`（峡谷之前）**都是 0** | **`k_storm.js` 的 `buildCanyon().update()` 写的是**：<br>`p.map.offset.y = (p.map.offset.y - (0.55*scroll*(1-freeze))/60) % 1`<br>—— **拿当前值再减一格**，于是滚动量按**渲染次数**累加、与 t 无关：同一个 t 渲几次就滚几格 ✗ | 改成**闭式相位**：把速率 `rate(τ) = 0.55·(1−0.92·f)·(1−f)`（`f = seg(f0,f1)` 是 hit10 的线性冻结斜坡）在 `[t0, t]` 上**解析积分**（`∫(1−1.92w+0.92w²)dw = w − 0.96w² + (0.92/3)w³`），再由每块屏的 `offset0` 推出偏移；调用方传入 `t0=p9t / f0=p10 / f1=p11` | **`t=156.43 / 157 / 158` 各连渲 3 次：`ab=0 / bc=0`** ✓ |
