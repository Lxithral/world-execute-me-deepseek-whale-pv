## ① 0:12 立绘上方的「两条黑线」

### 结论

是 **`closed` 情绪角色的 `eyesClosed` 叠加层**：`src/whale/sprite.js:120-131` 的 `drawOverlay()` 里**恰好两个 `fillRect`**，颜色 `rgba(8,10,14,0.92)`。

### 完整证据链

| 步骤 | 位置 | 内容 |
|---|---|---|
| 1. 触发 | `src/scenes/a_boot.js:84,88` | `const spriteA = span(t, 11.25, 12.15)` → `ctx.whale.sprite = { expr: 'closed', rect, alpha: spriteA }`。t=12.0 时 `spriteA = 0.75/0.90 = 0.833` |
| 2. 角色映射 | `src/whale/exprs.js:47` | `closed: { file: FISH('cheerful'), desat: 0.85, overlay: 'eyesClosed' }`（代码内已标 `UNCONFIRMED`，是我为"缺闭眼素材"做的兜底） |
| 3. 绘制入口 | `src/whale/sprite.js:273-275` | 因 `from === to`，走 `drawOne(sTo, 1)` 后调用 `drawOverlay(g, 'eyesClosed', …)` |
| 4. 画黑线 | `src/whale/sprite.js:120-131` | `ey = y + h*0.155`；`ew = w*0.075`；`eh = max(2, h*0.007)`；两个矩形分别位于 `x + w*0.46 - ew/2` 与 `x + w*0.60 - ew/2` |

### 1920×1080 实测几何（t=12.0）

`standRect(1920,1080)`（`src/whale/sprite.js:162`，默认 `aspect=0.5557`）给出立绘框 **x 1133.9–1746.1、y 162–1263.6**（`h = 1080*1.02 = 1101.6`，`w = 612.16`）。两条黑线：

| 位置 | 屏幕 x | 屏幕 y | 尺寸 |
|---|---|---|---|
| 左眼睑条 | ≈ **1392.6** | ≈ **332.8** | 45.9 × 7.7 px |
| 右眼睑条 | ≈ **1478.3** | ≈ **332.8** | 45.9 × 7.7 px |

即：落在她**头部/眼睛区域**（立绘上部的脸），不透明度 `0.92 × 0.833 ≈ 0.77`，叠在已 85% 去色的立绘上 → 观感就是"两条纯黑横条"。**生效窗口 ≈ 0:11.26–0:12.15。**

### 已排除的其他嫌疑

| 嫌疑 | 排除依据 |
|---|---|

## ② 53 秒「时间隧道只有一小条」

这是**两个原因叠加**，缺一不可。

### 原因 1（真 bug）：蒙眼黑条没有在时间尺开始前退场

`src/scenes/d_switch.js:92-99`：

```js
const blind = span(t, 47.9, 48.6) * (1 - span(t, 54.4, 55.4))
const slit  = 1 - blind * 0.82
const bar   = (H / 2) * (1 - slit)
```

t = 53.0 代入：`span(53,47.9,48.6) = 1`，`span(53,54.4,55.4) = 0` → **`blind = 1`** → `slit = 0.18` → `bar = 540 × 0.82 = 442.8px`。

上下各一条黑条：

| 元素 | 覆盖范围 |
|---|---|
| 上黑条 | `fillRect(0, 0, W, 442.8)` |
| 下黑条 | `fillRect(0, 1080-442.8, W, 442.8)` = y 637.2–1080 |
| **剩余可见带** | **y ∈ [442.8, 637.2]，仅 194.4 px 高**（画面高度的 **18%**） |

而 `blind` 从 48.6 一直满值到 54.4 才开始淡出，**完整覆盖了时间尺窗口 51.4–55.2**。

### 原因 2（实现缺口）：所谓"时间隧道"本来只是一条 2D 细尺

`src/scenes/d_switch.js:190-243` 的 `drawTimeline()` 全部几何：

| 元素 | 值 |
|---|---|
| 主轴线 y | **669.6**（`H*0.62`） |
| 轴线半长 | `half = W*0.44 = 844.8` |
| 刻度线 | y 661.6–677.6，**高 16px** |
| 年号大字 | 54px，`textBaseline='bottom'`，基线 y = 643.6（字形盒 ≈ 589.6–643.6） |
| 当前年 | t=53 时 `year ≈ 525`（由 `inOutCubic` 插值 2026 → −3000） |

关键：**主轴线的 y = 669.6 已经在可见带下沿 637.2 之外** → 轴线、刻度、刻度年号标签（y+12 = 681.6）、合拢圆点**全部被下黑条盖住**；唯一露进 194.4px 缝里的是那 54px 年号数字的顶端。

**净观感 = 一条横缝里飘着一个年份数字** —— 正是"只有一小条"。

### 叠加因素：眩晕旋转把它推得更低

`src/scenes/d_switch.js:35` 在 t=53 时 `dizzy = 1`，`src/scenes/d_switch.js:38-43` 把背景/示波器/**时间尺**（时间尺绘制在 `g.save()/restore()` 之内，`:67`）整体绕画面中心旋转 `1*0.24*sin(53*2.1) + 0.1 ≈ -0.134 rad ≈ -7.7°` 并放大 1.06 倍 → 轴线被推到约 **677px**，更靠下。

### 与 FIX 的对应

`FIX.md` §3 段 D：「travel: 全屏时间隧道(2.7)，年份巨字高速飞过；**修复"只有中间一小条"的 bug，隧道必须占满整个画面**」。
→ 既要去掉"黑条不该在场"这个时序错，也要把 2D 细尺换成真正的全屏 3D 隧道（沿 z 轴的环 + ≥200px 年号）。同时 `blind` 的收光圈效果按 §3 段 D 应改为"仅用暗角与光圈"，**不要遮立绘的黑条**。

## ③ 歌词「偏上」与「词距过大」

### ③-A 词距过大：已定量，根因是**等宽字体 + 把 LRC 的空格当间距用**

| 事实 | 证据 |
|---|---|
| LRC 的每个词条**自带尾随空格** | `public/data/lyrics.json` 中 **308 / 403** 个 `words[].w` 以空格结尾（如句 #0 的 `"Switch "`、`"on "`、`"the "`、`"power "`、`"line"`） |
| 排版原样测量与推进 | `src/lyrics/layout.js:74`（映射词表）、`:89-91`（`x += ww`）、`:32`（`wrapWords`）、`:50`（`lineWidth`）——**没有任何额外间距代码** |
| 字体是等宽 | `src/lyrics/layout.js:20-21`：`700 ${px}px "JetBrains Mono", "Microsoft YaHei", … monospace`，字重 700 |
| 空格推进 = **0.6 em** | 解码 `node_modules/@fontsource/jetbrains-mono/files/jetbrains-mono-latin-700-normal.woff2`：`unitsPerEm=1000`，所有可打印字符 advance `=600` |
| 当前词距 | `49.68px × 0.6 =` **29.81 px** |
| FIX 要求 | 单空格宽 **0.28 em ≈ 14.6 px**（`FIX.md:159`） |
| → **偏宽 2.05×** | 29.81 / 14.56 |

补充：每句**最后一个词**没有尾随空格，所以只有那处间距是"正常"的 —— 这也解释了为什么观感是"词与词之间散开的"。

### ③-B 偏上：几何上**不成立**，只有三处未达 FIX 规格的小偏差

我把 85 句全部实算了一遍（W=1920, H=1080）：

| 量 | 实测 | FIX 要求（`FIX.md:161`） | 差 |
|---|---|---|---|
| 英文基线 | `H × 0.88 =` **950.4 px（88.0%H）** | 0.885H = 955.8 px | **高 5.4 px** |
| 英文字号 | **49.68 px**（`H × 0.046`） | **≥ 52 px** | 小 2.3 px，**低于硬下限** |
| 中文字号 | **27.32 px**（`enFont × 0.55`） | **≥ 30 px** | 小 2.7 px，**低于硬下限** |
| 中文基线相对英文 | **+52.36 px（0.0485H）** | **+0.062H = 66.96 px** | **中文行偏高 14.6 px** |

- 两个"保护分支"**从未触发**：`zhBottom = 1006.04 < hardBottom = 1026`（`src/lyrics/layout.js:127-129`），`enTop = 911.65 > H×margin = 54`（`:131-132`）→ **`shift = 0` 恒成立**，位置恒定 0.88H。
- 另外 **85 句全部 `K=1`**（无一句需要断行：最宽的 #60 是 45 个字符 × 0.6em = 1341 px < `maxW = 1612.8`）→ 多行堆叠项 `-(K-1-k)*enFont*1.15`（`:82`）是**死代码**。
- 也排除了两类经典坐标 bug：**没有**"比例当像素"（`RATIO` 全部经 `H*`/`W*`/字号缩放）；**没有**"基线当顶边"（`:157`、`:167` 都正确减去了 ascent，渲染用 `textBaseline='alphabetic'`，`render.js:115`）。
- 代码里**不存在 `0.062` 这个常量**（全仓 grep 无命中）：中文间距用的是 em 相对公式
  `enFont*escape(10.93) + enFont*zhGap(17.39) + zhFont*cjkAscent(24.05) = 52.36px`（`src/lyrics/layout.js:122`）。

**结论（已与你确认）**：按 FIX 规格改排版即可 —— 基线 0.885H、英文 ≥52px、中文 ≥30px、中文基线 = 英文基线 + 0.062H、空格 0.28em、英文改**比例字体**，不再追查额外坐标 bug。

### 审计过程中顺带记录的两个"历史坑"（改的时候别再踩）

1. **不要用 `globalCompositeOperation='saturation'/'color'` 给立绘去色/着色**：整画布 `fillRect` 会把**透明区域填成不透明**（曾导致立绘变成一块灰底方块）。现方案是：去色走 `getImageData` 逐像素向亮度插值（保留 alpha，`sprite.js:makeDesat`），着色走 `source-atop` 蒙版平涂。
2. **WebGL 画布必须 `preserveDrawingBuffer: true`**，否则把它 `drawImage` 进 2D 合成层时读到的内容不确定，会破坏"同 t 渲染两次一致"的自检（见 `src/core/compositor.js` 构造参数）。

### ⚠ 发现的规格冲突（已决定，并按此实现）

FIX.md §2.5 同时要求三件事，在 1080p 逻辑坐标下**互相矛盾**：

1. 英文基线 = **0.885H** = 955.8px
2. 中文基线 = 英文基线 + **0.062H** = 1022.76px
3. 上下安全边距 **≥6%** → 内容底不得低于 1015.2px

中文降部（0.12 × 30px = 3.6px）会落到 **1026.4px**，比 6% 边距线低 11.2px。

**处理方式**：把 6% 底边距当作硬规则（它属于 §0.5 的可读性硬规则），据此反推英文基线上限 = 944.6px（**87.47%H**），即比 0.885H 低 11.2px；中文基线仍严格保持 +0.062H，中文降部正好落在 6.00% 边距线上。该值由 `layout.js` 的 `metrics.clampedByMargin / marginLimitFrac` 报出，`?debug` 可见；`?lyricY=0.9` 仍可手动抬高基线（会被 6% 边距再次夹住）。

这样处理也满足 selftest h)（英文基线 ≥0.80H）。**决策记录见 `docs/PROGRESS.md` 的决策日志。**
